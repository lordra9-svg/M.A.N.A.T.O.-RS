# Clean-room specification and process

**Status: DRAFT — awaiting approval.** No subsystem rewrite starts until this
document and `COMPATIBILITY.md` are approved.

## 1. Goal

Make M.A.N.A.T.O.-RS compatible with both:

- M.U.G.E.N 1.1 Beta content and behavior
- Ikemen-GO content and behavior

while keeping the engine and bundled content MIT-licensed and independently
implemented.

## 2. Definitions

- **MIT source**: source code, documentation, or assets licensed under a
  permissive license that allows study and reimplementation, with attribution.
  Ikemen-GO is the primary MIT engine reference.
- **Black-box oracle**: a running reference engine used only to observe
  inputs and outputs. Its source is not inspected during implementation.
- **Derived assertion**: a behavioral rule recorded in this repository after
  observing an oracle, for example “a guarded light hit advances the defender
  to state 150 for N ticks.” Raw oracle traces are not committed.
- **Strict clean room**: the implementation is written from the frozen
  specification, not by translating reference source. The same contributor may
  not consult the oracle while implementing a subsystem.

## 3. Source policy

Allowed:

- Ikemen-GO source and documentation (MIT).
- Public M.U.G.E.N format and engine documentation.
- Stock and user-provided content as input data.
- Black-box observations of Ikemen-GO.
- Original assets generated by this project.

Not allowed:

- Reading, searching, decompiling, or disassembling M.U.G.E.N binaries.
- Using `mugen-reimpl`, its binary, or any Ghidra/REA-derived reference.
  The checkout has been deleted.
- Copying, transliterating, or mechanically porting Ikemen-GO code.
- Committing raw oracle traces, screenshots, or extracted data as fixtures.

Historical note: an early prototype consulted `mugen-reimpl`. That reference is
deleted and the affected subsystems are listed for rewrite in section 6.

## 4. Process

1. **Audit** the current tree and mark every subsystem as clean, tainted, or
   unknown.
2. **Specify** each subsystem in `docs/spec/` using only allowed sources.
   Record source citations and derived assertions.
3. **Freeze** the subsystem spec and its compatibility-matrix rows.
4. **Implement** from the frozen spec without reopening the oracle.
5. **Verify** with unit tests, content tests, and derived-assertion oracle
   checks.
6. **Record** provenance for every subsystem in `PROVENANCE.md`.

Because the same contributors write the spec and the implementation, this is a
spec-first independent reimplementation, not a legally separated clean room.
The limitation is recorded explicitly rather than hidden.

## 5. Oracle policy

- Oracle: Ikemen-GO only.
- Oracle artifacts: derived assertions only; no raw traces or screenshots in
  the repository.
- Oracle runs must use deterministic input scripts and content already present
  in the test matrix.
- An oracle result is not a specification until it is written as a behavioral
  assertion with a test case.

## 7. Deliverables

- `COMPATIBILITY.md`: approved feature/behavior matrix.
- `docs/spec/`: one spec per subsystem, with citations and derived assertions.
- `docs/oracle/`: deterministic input scripts and expected derived assertions
  (no raw traces).
- `PROVENANCE.md`: current source policy and subsystem provenance.
- Tests for every matrix row marked `Verified`.

## 8. Acceptance

A subsystem is done only when:

- Its matrix rows are approved.
- Its spec is frozen and cited.
- Its tests pass in a clean export with no external content except the approved
  matrix content.
- Its behavior matches the derived Ikemen-GO assertions.
- Its M.U.G.E.N 1.1 content tests pass.
- No `mugen-reimpl` or M.U.G.E.N binary is used.
